# 技术文档：强化学习训练规格（首版）

本文档是写训练代码的规格。背景和总体设计见 `docs/rl_design.md`，交战环境见 `docs/engagement_spec.md`。这里的所有对象都是《战争雷霆》游戏内的单位和机制。

数值都是起点：参数量是按下面的结构逐层算出的；学习率、批量等超参数还没有本环境的训练结果支持，要靠第一轮曲线调整。

## 1. 决策与执行链

```
观测 → 策略（每 0.4 s 决策）→ 意图 → 保持 / 切换规则 → 玩家执行模型 → 飞行指令与镜头指令
```

- **脚本和策略输出同一种意图结构（第 3 节）**，经过同一个执行器。
- **模仿学习**记录执行噪声加入之前的意图。
- **PPO** 保存策略实际采样的动作和它的 log-prob，不能用执行器延迟、拒绝或修改后的结果代替。
- 保持规则通过动作屏蔽体现在策略内部（第 4 节），所以采样到的动作就是执行器接受的动作。

## 2. 观测

| 输入 | 宽度 | 内容 |
|---|---|---|
| 本机 | 96 | 约 48 个数值加有效性标志。<br>飞行状态；当前状态下的性能描述；导弹剩余和 Rmax、不可逃逸区；干扰弹；雷达参数；到地图边界的距离；对局时间。<br>新增：视角模式、镜头方向（相对机体的方位和俯仰，用正余弦）、自由视角已持续时间、当前保持状态与剩余保持时间、当前建议已发布多久。<br>能量：能量高度、剩余功率 Ps、表速与角点速度之比。 |
| 实体 | 每个 48，最多 64 个 | 约 24 个字段加有效性标志：<br>类型（雷达航迹、RWR、MAW、尾焰、目视、目标框、地图标记、队友、本方在飞导弹、推测来袭导弹）；<br>已知的距离、方位、俯仰、速度；<br>年龄、是否外推；是否锁我；识别出的机型性能；<br>本方导弹的支援状态。<br>对雷达航迹另加：敌机的能量估计，以及若现在发射，导弹的预计飞行时间和开机时间（对方的反应时间）。 |
| 上一条意图 | 48 | 各动作头的上一个取值及其持续时间，包括视角和键盘 |

- 连续量按固定尺度归一化，角度用正余弦，缺失值置 0 并带标志。
- 实体之间无序，不加位置编码。
- **只有模拟器真值不进 actor。** 动作屏蔽、实体排序也只能用观测计算，否则真值会间接泄漏进去。

**64 个实体的取舍顺序**：
1. 必保留：当前支援中的目标、机动参考对象、视角对象。
2. 来袭导弹相关：MAW、导弹告警、可见导弹标记。
3. 锁定我的雷达。
4. 雷达航迹，按距离由近到远。
5. RWR 告警：没有距离信息的，不当作无穷远，按类型（导弹 > 锁定 > 跟踪 > 搜索）和年龄排序。
6. 队友、地图标记，按距离。

超出 64 个的丢弃，并记录丢弃数量以便监控。

**镜头决定哪些东西看得见**：目视发现、尾焰、目标框和参数、导弹标记，只有在镜头视场内才可见；雷达 B 显、RWR、MAW、地图不受镜头影响。

- 视场默认水平 90°，训练时在 90–120° 随机（是水平还是垂直视场未定，D）。
- 镜头转动有速率上限，暂定 180°/s（D）。
- 交战环境里已有接口 `wt_overlay/engagement.py` 的 `Camera.sees()`，但目前对任何方向都返回 True。**具体的镜头模型要先实现，否则视角动作对观测没有影响，策略学不到观察。**

## 3. 动作（3 个指向头 + 12 个分类头）

| 头 | 选项 | 条件输入 | 何时可用 |
|---|---|---|---|
| 机动参考对象 | 实体 N + "不指定" | GRU | 瞄准视角 |
| 雷达 / 武器目标 | N + 1 | GRU + 机动参考 | 始终 |
| 视角对象 | N + 1 | GRU | 视角模式为"看对象" |
| 机动 | 11：保持 / 对准 / 左右偏转 30–50° / 左右三九 / 掉头 / 回中线 / 绕左 / 绕右 / 回家 | GRU + 机动参考 | 瞄准视角，且不在保持期 |
| 垂直 | 5：保持 / 爬升 / 中空 / 贴地 / 俯冲 | 同上 | 同上 |
| 速度 | 3：全加力 / 巡航 / 收油加减速板 | 同上 | 始终 |
| 箔条 | 3：不放 / 一包 / 连续 | 同上 | 有箔条时 |
| 雷达模式 | 3：TWS 宽 / TWS 窄 / STT | GRU + 两个对象 | 始终（STT 需要目标） |
| 天线俯仰 | 5：+20° / +10° / 0° / −10° / −20°（相对水平） | 同上 | 始终 |
| 武器 | 2：不发射 / 发射 | 同上 | 有弹且目标有航迹 |
| 视角模式 | 3：瞄准方向 / 看对象 / 看方向 | GRU | 始终 |
| 看方向：方位 | 8：相对机头每 45° 一档 | GRU | 视角模式为"看方向" |
| 看方向：俯仰 | 3：−30° / 0° / +30°（相对水平） | GRU | 同上 |
| 键盘滚转 | 3：左满 / 不动 / 右满 | GRU + 机动参考 + 视角对象 | 自由视角（看对象或看方向）时 |
| 键盘俯仰 | 3：推满 / 松 / 拉满 | 同上 | 同上 |

**条件顺序**：先选视角模式、机动参考，再选雷达 / 武器目标、视角对象，最后输出其余各头。

**指向头的结构**：
- 查询向量由 GRU 状态线性映射到 64 维；雷达 / 武器目标头的查询还拼接已选机动参考的特征。
- 键向量由每个实体的 Transformer 输出线性映射得到。
- 缩放点积打分，"不指定"用一个可学习的键向量表示。

**自由视角的规则**：
- 自由视角时屏蔽鼠标飞行（机动、垂直两个头），改由键盘头飞行；雷达、武器、箔条、速度照常可用。
- 键盘按满行程执行（`flight.KeyboardCommand`），受每架飞机自身的过载限制；舵量系数 `authority` 按玩家随机，默认 1。
- **退出自由视角的那一步**，机动和垂直两个头必须按当前观测重新给出，不沿用进入自由视角前的旧意图，保持计时也从这一步重新开始。

## 4. 保持规则

- **只约束高层机动意图**，即机动参考、机动、垂直三个头。一旦改变，至少保持 2.0 s。保持期内这三个头被屏蔽为"维持当前值"，只有一个合法选项，不产生梯度。
- **键盘、视角、雷达、武器、箔条、速度不受保持限制。**
- **计时从建议发布时刻开始**，也就是策略做出该决策的时刻，不从玩家开始执行的时刻算起。
- **紧急解除**：出现以下任一个**可见**的新告警时，保持立即解除：
  - RWR 导弹告警；
  - MAW；
  - 新的 STT 锁定；
  - 视场内新出现的导弹标记。

  不得读取模拟器真值（例如真实的剩余命中时间）。
- 剩余保持时间、建议已发布时长都作为观测输入，合法动作屏蔽同时交给策略。

## 5. 玩家执行模型：两条响应路径，不叠加

| 路径 | 开始执行的时刻 | 用在哪里 |
|---|---|---|
| 跟随建议 | 建议发布 + 跟随延迟 | 训练时策略控制的飞机（策略相当于给玩家的建议，玩家照做）；评估中"听建议"的玩家 |
| 自主反应 | 告警可获得 + 自主反应延迟 | 脚本飞行员；评估中"不听建议"的玩家 |

- 在评估的"建议提升"实验里，玩家按一定比例接受建议。接受时走跟随路径，拒绝或没有建议时走自主路径。**同一个动作不会先等自主延迟、再等跟随延迟。**
- **延迟的统计定义**：每个玩家每局抽一个个人中位数；每次事件在这个中位数附近按对数正态分布抽取，再截断到上下限。

  | 延迟 | 个人中位数（每局抽一次） | 每次事件的离散 σ | 截断范围 |
  |---|---|---|---|
  | 跟随建议 | 均匀分布 0.5–1.2 s | 0.3 | 0.25–2.5 s |
  | 自主反应 | 均匀分布 1.0–2.5 s | 0.4 | 0.5–5 s |

  命中概率模型里用的自主反应中位数 1.5 s 落在这个范围内。以上全部为 D 级。
- 其他执行误差：
  - 航向和过载的跟随误差：对机动意图的目标方向加零均值噪声，σ = 5°（D）；
  - 约 5% 的意图不被执行（D）。
- 传感器扫描、画面刷新带来的延迟由观测层处理，不算在这里。

## 6. 网络

**actor**：

```
实体（≤64 × 48）→ MLP 48→64→64（GELU）→ 2 层 pre-LN Transformer（d=64，4 头，FFN=128，dropout=0，无位置编码）
                → 注意力池化（Linear 64→1 打分，加权求和）→ 64
本机 96 → MLP 96→128→128（GELU）
拼接 128 + 64 + 上一条意图 48 = 240 → Linear 240→256 + LayerNorm + GELU → 单层单向 GRU256
→ 3 个指向头（用每个实体的 Transformer 输出）+ 12 个分类头
```

用 PyTorch 实现时必须显式写 `dim_feedforward=128`、`dropout=0`、`norm_first=True`，否则会用默认的 FFN 2048 和 dropout 0.1。

**critic**（独立权重）：
- 可见实体分支、本机分支、GRU 结构同 actor。
- 另加一个真值实体分支：飞机和导弹放在同一个集合里，每个 token 40 维，带类型标志。
  - 飞机：位置、速度、姿态、存活。
  - 导弹：位置、速度、目标是谁、动力与导引状态、支援状态。
  - 编码器结构与可见实体分支相同。
- 融合输入：128 + 64 + 64 + 48 = 304。
- 输出这架飞机的预期个人回报。

**参数量**（逐层计算）：

| 模块 | actor | critic |
|---|---:|---:|
| 可见实体编码（MLP + Transformer + 池化） | 74,305 | 74,305 |
| 本机 MLP | 28,928 | 28,928 |
| 真值实体编码 | — | 73,793 |
| 融合层 + LayerNorm | 62,208 | 78,592 |
| GRU256 | 394,752 | 394,752 |
| 3 个指向头（含"不指定"键） | 66,112 | — |
| 12 个分类头 / 价值头 | 16,050 | 257 |
| **合计** | **642,355** | **650,627** |

- 两者合计 1,292,982 个参数，float32 约 5.17 MB。HUD 只需要 actor，约 2.57 MB。
- 实体上限从 32 增加到 64 不增加参数，注意力的二次项计算量约变为 4 倍。
- 所有机型共用 actor 权重，每架飞机保留自己的 GRU 状态。

## 7. PPO

| 超参数 | 取值 | 说明 |
|---|---|---|
| 决策间隔 | 0.4 s | 记录实际间隔 |
| γ | 0.997997 | 0.995 的 0.4 次方，保持约 200 s 的时间尺度 |
| GAE λ | 0.979692 | 0.95 的 0.4 次方 |
| clip | 0.15 | 作用于联合动作的概率比 |
| 学习率 | actor 1e-4，critic 3e-4 | 两个 Adam 分开，β=(0.9, 0.999)，ε=1e-5，weight decay 0 |
| 梯度范数上限 | 0.5 | actor、critic 分别裁剪 |
| 每批训练轮数 | 3 | — |
| target-KL | 0.02 | 按联合动作的平均 KL；超过就停止本轮剩余的 actor 更新 |
| 熵系数 | 0.01 | 前 100 万决策保持；到 500 万时线性降到 0.003；过早塌缩就暂停衰减 |
| value clipping | 关 | 用回报标准差缩放的 MSE，尺度在每轮更新期间固定 |
| 精度 | float32 | — |
| 采样 | 同步，每轮用固定的行为策略版本 | — |

- **联合概率比**：3 个指向头和 12 个分类头的条件 log-prob 相加，对联合比只裁剪一次。被屏蔽、只剩一个合法选项的头，log-prob 为 0。
- **熵**：只对合法选项数 K > 1 的头计算，每个头的熵除以 log K 后取平均。
- **advantage**：在整批有效数据上统一标准化。奖励不按单局归一化。
- **奖励**：击落 +1，被击落 −2（含撞地），助攻 +0.3，团队胜负不计。

**批量**：

| 项目 | 取值 |
|---|---|
| 逻辑轨迹流 | 64 条 |
| 每条采样长度 | 320 步（128 s） |
| 每轮采样量 | 20,480 个有效决策 |
| BPTT 片段长度 | 80 步（32 s） |
| 预热（不计 loss） | 最多 16 步 |
| minibatch | 16 段 × 80 步 |
| 每轮更新次数 | 3 轮 × 16 个 minibatch = 48 次 |

- **按序列片段抽 minibatch**，不能把各时刻打散。
- GRU 状态跨片段延续；预热用片段之前的历史重新推进隐藏状态。
- 死亡、重置、padding 分别处理，padding 不进任何 loss 和统计。
- 逻辑轨迹流的数量与环境进程数无关。

## 8. 模仿学习（BC）

- **数据**：脚本对局，以"高手"水平为主，起始规模约 100 万个有效决策。另外统计独立对局数、场景数，以及发射、规避、回切等事件的数量；连续多步的"保持"不算独立案例。
- **划分**：按整局或场景分组，80% 训练、20% 验证。
- **训练参数**：
  - 片段 80 步，预热 16 步；
  - batch 为 32 段；
  - Adam 3e-4，梯度上限 0.5；
  - 最多 10 轮，验证损失连续 3 次没有改善就停。
- **损失**：各头的屏蔽交叉熵。训练时指向条件用示范中的对象选择。
- **类别加权**：发射正样本 ×5，机动切换 ×3，其余 ×1，在各自的头内按权重总和归一。
- **验收**：
  - 各头的验证损失；
  - 发射的 precision 和 recall；
  - 让模型自己飞，表现能否接近脚本。

  不只看动作准确率。

## 9. PPO 起步

- 保留一份冻结的 BC 策略做参考。它沿同一条实际历史维护自己的 GRU 状态。
- **actor 损失** = PPO 项 − 熵系数 × 归一化熵 + β × 平均 KL(π_BC ‖ π)。KL 只在各合法条件头上取平均。
  - β 取 0.05，前 20 万决策保持不变，到 200 万决策时线性降到 0。
- target-KL（限制一轮更新改动多少）和 BC 参考 KL（限制离初始策略多远）分开记录。
- critic 不单独预训练，随 PPO 开始训练。
- **S1 首轮预算**：100 万–500 万个有效决策，约 49–245 轮采样加更新。对手先固定为脚本人群，再引入历史策略组成的联盟。这个预算用来检查学习是否正常，不代表收敛所需的样本量。

## 10. 第一轮重点看的曲线与对策

| 现象 | 先做什么 |
|---|---|
| 联合 KL 经常顶到 0.02，表现跳变 | actor 学习率减半；仍然频繁就把训练轮数从 3 降到 2 |
| 熵过早塌缩，只剩"保持"或"不发射" | 停止熵衰减；检查动作屏蔽和稀有标签；再考虑把熵系数从 0.01 提到 0.02 |
| BC 在训练集和验证集上都欠拟合 | 才考虑加容量，例如 FFN 从 128 改成 256 |
| BC 验证很好，自己飞却很差 | 先查历史输入、条件动作和状态分布偏移，加参数通常不是首选 |
| critic 误差大、解释方差低 | 先查回报计算和 bootstrap，再调 critic 学习率或采样长度 |
| 训练分数上升，独立场景的收益不升 | 扩大场景覆盖和对手多样性，检查是否只学会了对付训练脚本 |
| 自由视角从不用，或一直用 | 先确认镜头模型确实改变了观测（第 2 节），再看键盘飞行的执行是否正确 |

## 12. 实现前要先具备的环境能力

1. 具体的镜头模型：替换 `Camera.sees()`，包括视场、镜头转速、看对象和看方向两种模式。
2. 意图执行器：把第 3 节的意图换成飞行指令和镜头指令，并处理保持规则（第 4 节）和两条延迟路径（第 5 节）。打法脚本改为输出同一种意图。
3. 观测编码器：按第 2 节输出本机、实体、上一条意图三部分，以及合法动作屏蔽。
4. critic 用的真值实体：飞机和导弹，只交给 critic。
5. 局面保存与恢复：课程 S3 要从整局截取局面。
6. 多智能体接口：每架由策略控制的飞机一条轨迹，包括死亡、重置和 padding 的处理。

## 13. 环境与训练代码之间的接口契约

环境侧（第 12 节，`wt_overlay/rl_env.py`）和训练侧（`rl/` 目录）分开实现，只通过下面的接口连接。

**环境侧要求**：纯 Python，不用 numpy，能在 PyPy 下运行。

```python
env = MatchEnv(config: dict, seed: int)
obs = env.reset()                         # {agent_id: AgentObs}，只含由策略控制、仍然存活的飞机
obs, rewards, dones, info = env.step(actions)   # actions: {agent_id: {head_name: int}}
```

**决策间隔**：每次 `step` 推进 20 个节拍，即 20/48 = 0.41667 s。训练侧按实际间隔 Δt 计算每步的 γ = 0.995^Δt、λ = 0.95^Δt。

**`AgentObs` 的字段**：全部是 Python 的 list 和 float，便于跨进程传输。

| 字段 | 形状 | 说明 |
|---|---|---|
| `own` | 96 | 第 2 节"本机" |
| `entities` | n × 48，n ≤ 64 | 第 2 节"实体"，已按取舍顺序排好 |
| `prev_intent` | 48 | 第 2 节"上一条意图" |

| `dt` | float | 本步实际间隔 |

| `view_object` | n + 1 |
| `maneuver` | 11 |
| `vertical` | 5 |

**条件顺序**：`view_mode`、`maneuver_ref` → `target`、`view_object` → 其余各头。

环境侧另外提供一个函数，在已选的 `view_mode` 和对象确定之后，给出剩余各头的合法选项。训练侧按条件顺序采样时调用它，以便正确屏蔽条件相关的选项。也可以由环境把所有可能的条件组合都预先算好；两种做法选一，并写进接口文档。

**rewards / dones / info**：
- `rewards`、`dones` 以 agent_id 为键。
- 被击落或撞地的那一步给出奖励，并设 `done = True`；此后这个 agent 不再出现在 `obs` 里。
- 整局结束时，所有剩余 agent 的 `done = True`；超时结束时 `info["timeout"] = True`。超时局用价值网络 bootstrap，不当作终止状态。
- `info` 里带事件计数：发射、击落、助攻、死亡、丢弃的实体数。

**意图标签**：BC 数据由脚本经同一接口产生，环境提供 `env.scripted_actions()`，返回本步脚本提出的意图，格式同 `actions`。

**局面保存与恢复**：`state = env.snapshot()`，`env.restore(state)`。

**训练侧的假环境**：在真实环境完成之前，训练侧自己实现一个 `FakeMatchEnv`，严格遵守上面的形状和规则：随机实体数、随机屏蔽、随机死亡和超时。用它端到端测试采样、BC、PPO、检查点和多进程框架。

### 13.1 条件屏蔽的格式（定稿，取代上面"两种做法选一"）

动作在训练进程里采样，拿不到环境对象，所以条件屏蔽由环境预先算好，放在 `masks` 里发过来。各头的格式：

| 头 | `masks[头]` 的形状 | 依赖 |
|---|---|---|
| `view_mode`、`speed`、`chaff`、`antenna`、`target` | 一维 list[bool] | 无条件 |
| `maneuver_ref`、`view_object`、`look_az`、`look_el`、`kb_roll`、`kb_pitch` | 3 × 选项数 | 按 `view_mode` 取第几行 |
| `maneuver`、`vertical` | 3 × 2 × 选项数 | 先按 `view_mode` 取行，再按 `maneuver_ref` 是否为"不指定"（1 表示不指定）取 |
| `weapon`、`radar_mode` | (n + 1) × 选项数 | 按已选 `target` 取第几行 |

- 采样顺序：`view_mode` → `maneuver_ref`、`target`、`view_object` → 其余各头。每个头按上表取出对应的一维屏蔽。
- 保持期间被锁定的头，屏蔽里只有当前值一个为 True。
- 环境保证每个被取到的一维屏蔽至少有一个 True。

### 13.2 修订（2026-10-05）

- 天线俯仰头改为 5 档（+20° / +10° / 0° / −10° / −20°）。原因：N035 这类雷达的 TWS 上下只覆盖约 ±4°，3 档会出现扫不到的高度带。actor 参数量因此增加 770 个（两个新增选项 × 385），合计 643,125。

## 14. 实现说明（训练侧 `rl/`，2026-10-05）

记录实现时做的、规格没有明确写出的决定。运行方法见 `python -m rl.train --help`；契约检查工具：`python -m rl.check_env --env wt_overlay.rl_env:MatchEnv --config '{...}'`。

- **掩码格式**按 13.1 实现。传输时每个观测的全部掩码合成一个补零到固定宽度的字节块（指向头宽度和 `target` 行数补到 65），旧的 `head|cond` 条件表键会被拒绝。被取到的一维屏蔽若全是 False（环境错误），训练侧改用该头的默认选项并计数（`mask_fallbacks`）。天线头按 13.2 为 5 档，actor 参数量 643,125（3 档时 642,355，测试同时验证）。
- **Δt 与折扣**：每步的 γ、λ 用该步观测的 `dt`（`dt <= 0` 时取 20/48）：γ = 0.995^dt = 0.997914，λ = 0.95^dt = 0.978855。第 7 节表里的 0.997997 / 0.979692 是 Δt = 0.4 s 的值；契约（第 13 节）要求用实际间隔，所以训练用前者。
- **超时的最终观测**：整局超时时，`obs` 必须仍然包含每个存活 agent 的最终观测（`done=True`），训练侧据此用价值网络 bootstrap；被击落的 agent 不在 `obs` 里，按终止处理。没有最终观测的超时 agent 退化为用该步自己的价值 bootstrap。整局自然结束（不是超时）按终止处理。
- **轨迹流与 reset**：一条流绑定（env 实例，受控 agent 槽位），`env.streams_per_env` 是一局中受控 agent 数的上限（`reset()` 返回更多会报错）。agent 死亡后其流补 padding，直到该 env 开新局；没有存活的受控 agent 或整局结束时，worker 自动 `reset()`。`valid_fraction` 记录在每轮指标里；每局只控 1 架（`streams_per_env=1`）时没有闲置。
- **隐藏状态**：actor 的 GRU 状态在采样时保存（每个片段窗口起点），critic 状态在采样后重推；上一轮最后 `burn_in` 步复制到下一轮前面做预热。BC 参考策略冻结，每轮采样后沿整轮实际历史 teacher-forcing 重推（状态精确），并保存各头分布用于 KL。从检查点恢复时 env 和隐藏状态重新开始（首步 `first=True`）。
- **target-KL**：每个 minibatch 更新前，用联合动作的 k3 估计 KL；超过 0.02 就跳过本轮剩余的 actor 更新（critic 继续）。指标里同时记录触发停止的那个 KL（`kl_target_max`）和对 BC 参考的 KL（`kl_ref`，分头 `kl_ref_head`）。
- **BC**：脚本意图在记录前按掩码规范化（只有一个合法选项的头强制为该选项，例如自由视角时的机动头；多选项下非法的改为最近的合法项并计数，应为 0）；真值 token 不进 BC 数据；窗口从零状态开始，窗口前 16 步只预热。BC 之后让策略自己飞，报告每决策奖励和事件率并与脚本对比。
- **`info["events"]`** 的键：`launch / kill / assist / death / dropped_entities`，每步的整数增量（受控 agent 合计）。`AgentObs` 可以是对象（属性）或 dict。


## Implementation notes (env)

`wt_overlay.rl_env.MatchEnv` 实现第 13/13.1 节；运行时仅用 Python 标准库。训练入口可用
`--set env.cls=wt_overlay.rl_env:MatchEnv`，`rl/` 无需修改。

- 默认 1 对 1、只控制 slot 0；`team_size=1..16`，`controlled="all"` 或 `policy_ids=[0,...]` 指定受控槽位；兼容假环境的 `n_agents`（控制前 N 个槽位）和 `max_steps`（时间上限为 N×20/48 s）。`teams` 为两组 `match.scenario` 的机型/打法/技术水平字典，支持不对称人数；`range_km` 指定出生线距离。`model/model_path/aircraft_pool` 控制 BR 机型池和打法先验。配置示例：`{"team_size":4,"policy_ids":[0],"time_limit_s":120}`。
- `fov_range=[90,120]`、`rcs_m2=5`（也可用机型或整数槽位为键的映射）、`multipath_gain=null`（关闭）、`missile_marker_range_m=10000`、`reach_dir`、`target_selection` 均可配置。`execution` 支持 `hold_s/error_deg/reject_p/authority/delay`；`delay` 的 `follow/autonomous` 各支持 `median_range/sigma/bounds`。每名玩家每局只抽一次个人中位数，意图事件在该中位数附近抽样，重复相同持续意图不重新启动延迟。独立的发射/单包箔条请求按事件处理；连续箔条按执行状态每 0.5 s 一包。
- `AgentObs` 是有字段的 dataclass，数值为 list/float。`masks` 精确采用 13.1 的条件表；训练侧按原采样动作存 log-prob，执行器不改写该动作。内部指向头保存观测实体的稳定 key，每步翻译为当前实体索引，最后一项为不指定。保持中的参考对象若暂时失去观测，保留最后观测的外推 token；不把它当作可发射的新航迹。保持仅约束瞄准模式下的参考/机动/垂直。退出自由视角重新取这三头，重启保持期。告警解除只看 RWR 导弹/锁定、MAW、新可见导弹标记。
- `own/entities` 使用 `rl_observation.OWN_FIELDS/ENTITY_FIELDS` 声明的顺序：前半部为归一化数值，后半部为逐字段有效性。角度用正余弦，位置尺度 64 km、高度 20 km、速度 1000 m/s、距离 120 km、能量高度 40 km、Ps 300 m/s、飞行/开机时刻 300 s。上一意图为 15 个归一化头、15 个持续时间（60 s）、15 个有效标志及发布年龄/保持剩余/发布视角模式。critic 真值使用 20 个数值加 20 个标志，最多 128 token，飞机优先，剩余空间给近处导弹；只在 actor 观测和屏蔽构造完后独立编码。
- 当前 Pk 接口只给不规避目标的 Rmax 与概率线，没有定义可作为不可逃逸区的接口。`own.rne` 暂为无效（数值与标志均 0），不会把 Pk50 或背离 Rmax 冒充不可逃逸区。敌方未知机型不读取真值：视场内目标框可识别，RWR 的雷达型号仅在唯一对应机型时识别；其他情况类型标志为无效，机体正过载描述与雷达可转动范围取当前 BR 机型池的等权平均；已识别的机型取该型号的 FM（质量空重×1.3）与设备描述（D）。实体的水平位置可由方位/距离与本机坐标还原，不另占两个特征。能量估计只由航迹测得的位置/速度产生。
- `Pilot.propose()` 给 `Intent`，`ScriptController` 和 `MatchEnv` 都走同一 `IntentExecutor`。`Pilot.decide()` 保留原几何 Action 适配器供已有低层调用/测试；生成的 `Match.engagement()` 默认启用意图层。原脚本的自主反应等待在 `propose` 路径关闭，执行器承担唯一的自主反应延迟。连续几何航向/高度量化到第 3 节的离散动作，因此路径与里程碑 A 会有差异；没有隐藏连续飞行指令旁路。爬升完成按实际执行的 8 km 高度档判定，避免原 7.5–9 km 随机目标在离散档下永远无法到达。第一阶段侧移角量化为 ±40°，高度档为 11 km/8 km/100 m，俯冲指向比当前低 3 km；巡航为 85% 油门。
- 相机采用水平视场、16:9 透视投影和水平稳定的镜头轴（D）。生成的对局与训练环境使用真实视场与 180°/s 联合方位/俯仰限速。`OPEN_CAMERA` 保留给原低层 `Engagement` 的兼容调用；显式 `Camera()` 默认 90°。雷达/RWR/MAW/地图不受视场影响；敌方地图标记只有平面坐标。9500 m 以上航迹云在视场内无限距离可见。目标框有距离/接近率/机型；雷达框距离/速度取测量，目视框参数为 HUD 近似（D）。
- `step` 始终推进 20 个节拍；若在中途结束，完成剩余节拍再返回，`dt=20/48`。超时保留存活受控飞机的最终观测，其他整局终止返回空观测。死亡后不再返回该 agent；奖励与 dones 的键只含本步行动的存活 agent。一方全灭但仍有在飞导弹时继续结算到导弹结束或超时。误伤只给受害者 −2，不给误伤者击落/助攻奖励。`info.events` 包含基础五项，以及 `friendly_fire/retarget/crash/out_of_bounds/missile_error`。
- `snapshot/restore` 复制整个可变图：随机状态、飞机积分器及量化缓存、雷达/RWR、导弹/代理/支援回调、脚本、保持期与待执行队列、实体记忆和当前屏蔽。只共享不可变 FM 源数据和气动力表。导弹支援用可复制的 callable 对象，避免闭包指向保存前的世界。恢复不重新采样也不调用观测生成器。
- `scripts/build_reach_table.py` 通过公共逐步推进 API 求直线、不规避目标的可达边界，保存飞行与开机时间。网格默认 4×3×3×3（目标高度越界的点跳过）、每弹型一文件；边界容差 250 m、上限 120 km、目标 300 m/s。边界以二分求解，低端不命中时先做 12 个探针，边界仍命中则标 censored，不充当精确 Rmax。保存到原子替换的 JSON，每完成一个点即落盘；同网格/选项可续算，最多 48 进程。`--limit 1 --workers 1` 用于本机极小测试，完整表只在 workstation 运行。缺表/缺网格点/超出域时，脚本退回原 Pk Rmax，时间字段保持无效，不在训练进程实时仿真或外推。
- 超时奖励（可选）：`MatchEnv` 配置 `timeout_reward`（缺省不设，行为不变：超时用价值网络 bootstrap）。设了以后（S1 用 −0.5），打满时间时每架仍活着的策略飞机在最后一步加上这个值，超时变成终止状态：`info["timeout"]` 为 False（不 bootstrap），另给 `info["time_limit"]` 为 True；最后一步不再返回观测。用户 2026-10-06 定：躲到结束不白拿 0 分。
- 坐标无关的观测（可选，用户 2026-10-06 要求）：`MatchEnv` 配置 `observation_frame`，缺省 `"world"`（行为不变），`"egocentric"` 时观测里不再有地图坐标、罗盘航向和队伍编号。自身向量同宽，原 11 个槽位改为：自家基地和敌方基地的距离与相对机头的方位（sin/cos）、离最近地图边的距离（出界为负）、正前/右/后/左方向离地图边的距离（`rl_observation.EGO_OWN`、`OWN_FIELDS_EGO`）。实体的方位改为相对机头，水平速度改为（右、前）分量。评价网络的真值令牌改为以自身为原点、按自身航向旋转（高度仍为绝对值）。动作本来就是相对的（相对实体、机头、地图中心、自家），不用改。
  - 起因：自博弈录像里，只当过南边一方的策略换到北边就失常（同一存档自己打自己，南边赢 107/120）。真实地图的出生点也不一定正南正北，可能是对角线或偏一边。

- 脚本扰动（可选）：配置 `script_perturbation`（字典，键见 `archetypes.PERTURBATION`），只影响对脚本局里脚本机的参数，见 rl_design 2.1。缺省不设，行为不变。
- 自博弈第一步（1v1）：`MatchEnv` 配置 `self_play_prob`（默认 0，缺省时行为和随机数序列都不变）。每次 `reset` 用局内随机数抽一次：按该概率让所有飞机槽位都由策略控制，否则仍按 `controlled`/`policy_ids`（默认槽位 0，对脚本局）。局类型记在 `env.episode_kind`（`self_play`/`vs_script`）、`info["episode_kind"]`、`info["self_play"]`、`info["events"]["self_play_decisions"]` 和场景串后缀 `:self_play`（仅配置里有该键时输出）；胜负仍由奖励得出。训练侧：`streams_per_env` 必须不小于一局最多受控数（1v1 自博弈为 2，`Config.validate` 检查）；对脚本局另一条流整局补 padding，`p=0.5` 时 `valid_fraction` 约 0.75。指标里的 `outcomes`/`win_rate`/`exchange`（及 `per_aircraft` 的胜负计数）只统计对脚本局，没有则统计全部；新增 `outcomes_by_kind`（每类的胜负、击落/被击落、`episodes`、`win_rate`、`exchange`、`decisions`，按 agent 计，自博弈胜率按构造约 0.5）。
- 新旧对战：`python -m rl.eval_replay --run-dir RUN --stats N --opponent-checkpoint PATH`，槽位 1 由该冻结策略飞（两个槽位都由策略控制，各用自己的带种子随机数），统计槽位 0 的胜率与交换比；默认仍是脚本对手；检查点先复制到临时目录再读。从已有检查点开始自博弈：把检查点放进新 run 目录的 `ppo/`，用 `python -m rl.train ppo --config <原 config.json> --run-dir <新目录> --set ...`（`ppo` 不重做 BC）；`--set env.config=...` 按 `ast.literal_eval` 解析，要写 `None`/`True`，不能写 JSON 的 `null`/`true`。
