# WT Energy

Windows 8111 透明能量 HUD 与静态 SEP 研究原型。显示层使用 PySide6；遥测、能量与 FM 计算仍只使用 Python 标准库。

## 在 Windows 上运行

使用 Python 3.11 或更新版本。将整个目录复制到 Windows 后，双击 `start_windows.cmd`。启动器会在项目的 `.venv` 中创建独立环境，并在首次运行时安装 PySide6，因此首次运行需要联网。准备完成后，图形界面使用 `pythonw.exe` 独立运行，双击启动产生的命令窗口随即关闭；`--headless` 和 `--help` 保留控制台输出。图形启动出错时会弹出错误提示，记录保存在 `%LOCALAPPDATA%\WT Energy\startup.log`。

将战雷显示模式设为 **全屏窗口**。默认连接本机 `http://127.0.0.1:8111`；HUD 自动跟随战雷窗口，切出游戏或最小化后隐藏。每次启动都会打开设置，关闭设置即可回到游戏；随后可用 `Ctrl+Alt+S` 或托盘菜单重新打开。没有有效遥测时指标显示 `—`。未检测到游戏时，可进入布局模式或合成演示预览。

先查看合成演示，可在项目目录的终端运行：

```bat
start_windows.cmd --demo
```

默认按 8111 返回的机型自动加载内置 FM，无需逐个找文件。设置页的“机型”列表可按中英文名称搜索，也可手动指定。机型不明或不在目录中时停止模型预测。

手动选择苏-27SM，使用 **23,000 kg 参考总质量**：

```bat
start_windows.cmd --aircraft su_27sm --mass-kg 23000
```

也可通过托盘菜单或 `Ctrl+Alt+S` 打开独立设置，切换实时／演示模式、选择机型或 FM 文件、输入质量和切换模型军推／最大推力。23,000 kg 只是示例输入，不是自动识别的本机重量。手动质量不会随燃油或机型自动变化，换机后需要重新输入适用的总质量。未手动指定时，仅接受遥测中明确提供的总质量，不从空重与燃油拼出实机重量。

机型切换会取消旧爬升规划并重新计算。手动选定的机型仍须与实时机型匹配；“自动识别机型”可恢复自动切换。设置页“当前模型”显示自动识别结果及游戏返回的机型标识；“手动载入 FM 文件…”是可选按钮，不代表自动识别失败。短暂读取失败时保留已加载模型但停止预测，收到同一机型的有效数据后恢复；加载失败每两秒重试。合成演示不自动选择机型，需要手动选择或使用 `--aircraft`。原有 `--model data\fm\su_27sm.blkx` 继续加载最初版本的回归样本。

显示与分组交互参考 [WTRTI 的 OSD / Groups](https://mesofthorny.github.io/WTRTI/features/)，使用 Qt 自行实现，并未复用 WTRTI 的程序或素材。战斗 HUD 背景完全透明，只绘制带描边的文字；无标题栏，不接受焦点，鼠标穿透到游戏。

| --- | --- |
| `Ctrl+Alt+O` | 显示／隐藏 HUD |
| `Ctrl+Alt+L` | 进入／退出布局模式 |

布局模式中，拖动“飞行状态”“实际能量”“动力与燃油”“静态参考”四个指标组；退出后恢复鼠标穿透。位置以游戏窗口内的相对位置保存，字体、字号、强调色、各组和各指标开关也会保存到本机用户配置。默认字号为 11，旧版配置首次升级时也会缩小，之后保留用户选择。设置中可以恢复默认位置、选择备用屏幕或关闭自动隐藏。关闭设置会完成布局并收起；退出程序使用设置或托盘中的“退出”。若系统托盘和设置热键都不可用，关闭设置会退出程序，避免留下无法操作的 HUD。

战斗 HUD 只显示指标名、数值和单位，组标题仅在布局模式显示。连接状态、字段定义和模型说明放在设置页；演示模式保留简短的 `DEMO` 标记。当前真空速不在 HUD 中重复显示。

设置页提供 22 项独立开关，默认启用 15 项：过载、迎角、侧滑角、俯仰角、滚转角、SEP、比能高度、爬升率、动能变化率、加速度、燃油、推力、参考 SEP、参考峰值 TAS、参考峰值 SEP。航向、垂直速度原始值、表速、高度、马赫数、第一台发动机油门、遥测总质量可按需开启。字段缺失时显示 `—`，不会用演示值补齐。

热键若被其他软件占用，设置界面会显示注册失败，仍可使用托盘菜单。独占全屏覆盖不在当前保证范围内；Windows 原生穿透、全局热键和游戏窗口跟随需要在 Windows 游戏环境实测。

## 爬升引导

爬升引导默认关闭。加载匹配的 FM 并设置总质量后，在设置页输入目标高度和可选的到达最低 TAS，点击“应用目标”。高度单位为 m，速度单位为 km/h；速度留空时，选择目标高度上静态 SEP 最大点的速度作为到达门槛。目标设置会保存，开启状态不随重启恢复。

使用 `Ctrl+Alt+C`、托盘菜单或设置中的开关启用。按照模型选择使用全军推／全加力，以俯仰操纵跟随指示条：白点在右侧时抬高，在左侧时压低，使白点保持在中央绿区。绿区对应航迹角误差 ±1.5°，整条刻度为 ±12°，超出后白点停在端点。它比较的是 **目标航迹角与实际航迹角**；实际角度由垂直速度和 TAS 计算，经 0.5 秒低通后同时用于“当前航迹角”数值和白点。不会把机头俯仰角当成航迹角。

引导组显示“加速／爬升／收平／到达”、目标 IAS、当前航迹角、目标航迹角和剩余高度。需要先平飞加速时，目标速度取参考线上后续进入爬升的速度；爬升后取随能量更新的跟踪速度。两者都换算为当前高度下的表速供跟飞。接近目标高度时逐渐收平，达到高度误差 ±25 m、TAS 不低于到达门槛、航迹角绝对值不超过 1.5° 后显示“到达”并收起白点。软件不发送任何飞行控制输入。

能量、推力和速度跟踪计算始终使用 TAS。HUD 的目标 IAS 按同一时刻的遥测换算：`IAS_target = TAS_target × IAS_current / TAS_current`；IAS 缺失、为零或无效时显示 `—`，角度引导仍可工作。这是当前状态附近的局部比例估计，没有另建皮托管可压缩性或仪表修正模型，不能保证大幅速度变化时的精确换算。到达速度设置及原有命令行参数仍明确使用 TAS，已有目标的单位不会改变。合成演示的 IAS 由标准大气密度生成，仅用于演示显示。

爬升组可在启用后进入布局模式独立拖动，沿用透明背景和鼠标穿透。关闭引导会立即隐藏该组，并取消后台规划；其他指标保持显示。总 HUD 开关仍控制所有组。数据失效、机型不符、质量缺失或模型不支持对应状态时，不显示角度指令。滚转角绝对值超过 30° 时提示“改平”。

规划使用比能高度 `E_s = h + V²/(2g)`，在每条等能量曲线上搜索 `P_s` 最大点，再连接成速度参考线；它与原有“同高度局部 SEP 峰值”指标各自独立。搜索限制为 0 至目标高度、80–650 m/s，并由 FM 的有效包线进一步约束。每个能量层间隔不超过 250 m，采用全区间 49 点粗搜和两次局部细化，无有效正 SEP 路径时停止规划。计算在后台进行；目标、机型、FM、模型推力档或参考质量改变后重新计算。使用遥测总质量时，累计变化超过 1% 触发更新。

实时跟踪采用 `a_cmd = V_ref'(E_s)·P_s + 0.08·(V_ref−V)`，再由 `h_dot_cmd = P_s−V·a_cmd/g` 得到航迹角。反馈优先使用遥测 SEP，并施加 1 秒低通；能量窗口尚未就绪时使用静态模型 SEP。角度限于 −5° 至 45°，目标指令以 2 秒时间常数平滑，变化率上限为 1°/s。数据中断或重新开启时，以新的当前角度初始化。接近末端时，将参考线平滑过渡到目标高度对应的等能量速度，并用剩余高度／12 秒限制爬升率，避免把整条参考线的末端当作瞬间可完成的拉起或收平。

这里实现的是**经典能量近似下的 SEP 最大参考线，以及带终端收平的人工跟踪引导**，不是完整瞬态动力学下经证明的最短时间解。等能量线方法假定高度与速度之间可快速交换；实际跟踪器限制下降、角度和变化率，转场、操纵滞后和收平会改变用时。到达速度是下限，不保证恰好以该速度到达，也不同时保证到达速度最大。离散搜索可能漏掉窄峰，参考线跳支和捕获段没有最优性保证。

规划沿用现有静态推力、部件气动和 1g 干净构型计算，不增加配平、挂载、燃油消耗或发动机瞬态模型；大航迹角时的升力需求变化也未重算。内置机型通过同一接口生成参考线；仅在所选质量、构型和目标存在有效正 SEP 路径时提供引导。闭环检查使用理想质点运动和两秒操纵滞后，**不是战雷内的最优爬升验证**。完整模型范围见下文。

## 键盘转向引导

在设置页的“键盘转向引导”选择 **30°／45°／90°／120°**，设置允许损失高度、最低 TAS 和响应参数，然后用 `Ctrl+Alt+T` 开启。首次取得连续姿态数据时记录初始速度方向，以后显示相对此方向的三维夹角；不累计盘旋路径角度，也不把机头航向变化当作速度方向变化。

HUD 显示阶段、动作、油门、目标转角、已转角度、剩余角度和参考用时。动作使用“左滚／停止滚转／右滚”与“推杆／松杆／拉杆”的组合；油门单独显示“收油／保持／加油”及当前值、下一动作段的目标值，例如 `收油 110 → 80%`。按游戏中自己的键位执行；软件不会读取或发送按键。方向舵保持中立，飞机保持干净构型。开启转向引导会关闭爬升引导，反之亦然。

首次达到目标角度后显示“到达”并撤下动作提示，状态保持到重新开始；它不指示后续如何收住或保持新方向。`Ctrl+Alt+R` 或设置页、托盘的“重新开始转向”重新捕获起始方向。关闭开关立即隐藏转向组。转向设置和位置会保存，开启状态不会随重启恢复。

短暂断线、姿态采样不连续或超出机动限制会撤下旧动作，保留初始方向和高度下限；恢复连续有效数据、回到限制范围后继续。速度／高度／载荷超限在 HUD 显示简短状态，具体原因保留在设置页。数据中断超过 2.5 秒、换机或修改质量／FM／推力档／后掠后，已捕获目标的会话须重新开始；不会偷偷把起点换成新方向。缺少姿态、AoA、AoS、垂直速度、油门、机型或总质量时不提供动作。俯仰接近垂直（`|Vy|/TAS >= 0.985`）、侧滑超过 ±10°、迎角不在共同失速前范围时同样暂停。高度限制是相对开始高度的损失上限，使用海拔高度，并不包含地形避障。

**动态参考的定义与边界：**

- 平动是三维质点模型：速度向量与垂直于它的升力方向为状态，包含重力、升力、阻力及推力的切向／法向分量；不强制水平转弯。升力方向随滚转和航迹转动更新。气动力使用所选 FM 的同一套部件 polar，推力使用原有发动机表；既有 SEP 和爬升公式保持原样。
- 载荷状态是 `L/(mg)`，由当前 AoA 与 FM 估计，不使用机体 Ny 代替。每个积分步在共同失速前迎角范围内求有符号升力需求，允许负升力，并将达不到的需求限制在有效区间内。响应状态描述载荷建立和滚转建立，不求完整机身角运动、舵面力矩或教官闭环。
- 速度方向由罗盘、俯仰、滚转、AoA、AoS 重建水平投影，再用 `Vy/TAS` 确定航迹角。采用东、北、上坐标，正俯仰为抬头，正滚转为右翼下沉；沿用现有姿态字段的符号约定，仍需在 Windows 中逐机型核对。风为零，不能据此恢复有风情况下的精确地速矢量。滚转率从连续升力方向的转动估计，排除航迹转动分量，并用 0.25 秒低通；没有把欧拉角变化率直接当作机体系角速度。
- 滚转、俯仰、油门各取 `−1/0/+1`，共 27 种组合，油门边界处跳过无效的增减动作。拉杆／推杆对应所设正／负载荷目标，中立俯仰近似抵消升力方向上的重力分量；滚转中立按响应时间衰减滚转率。**这不是鼠标瞄准教官的恢复规律**：实际松键响应还受鼠标指向、教官、飞控、改装、机组和速度影响。
- 油门从实时读数开始，以默认 **50 个百分点/s** 增减；保持输入维持当前油门。允许加力且发动机有加力时搜索至 110%，否则至 100%，最低 0%。推力参考使用原始全军推、全加力表：0–100% 按军推比例线性缩放，100–110% 在两档间插值，并加入默认 **1 s** 的一阶响应。初始推力状态按首个油门读数估计，之后按读数更新。**部分油门曲线、零油门推力和响应时间是项目近似，未经游戏标定**，不代表真实慢车、熄火或发动机控制律。油门变化速度、响应时间可在设置页调整；不影响原有 SEP／爬升计算。较低速度可能增大转向角速度，但升力能力也随速度变化，搜索仍检查最低速度和载荷约束，不固定要求收油。
- 默认满滚转参考速度 **120°/s**、滚转一阶时间常数 **0.35 s**、载荷一阶时间常数 **0.6 s**、人的反应时间 **0.3 s**、动作保持时间 **0.6 s**。默认正／负载荷范围 **+9/−3**，最低 TAS **360 km/h**，允许损失高度 **500 m**，预测上限 **15 s**。这些是可调整的项目参考参数，**不是从每架飞机 FM 复刻出来或已用游戏数据标定的结果**；同一组参数会沿用到其他机型，需要重新检查。尚未实现按键试飞记录与自动辨识。
- 后台使用有限宽度的动作段搜索，最多保留 27 条不同首动作分支，每段保持所设时间，积分步长不超过 0.15 s。先预测人的反应延迟，再搜索动作；在找到的候选中优先比较首次到达时间，同一步达到时再比较剩余比能。每次计算预算 0.8 s，最多每 0.8 s 发起一次新搜索。搜索剪枝、离散步长、时间预算与近似模型均不支持全局最优保证。
- 只有候选确实在预测范围内达到目标，才显示“参考用时”；只有部分转向进展时可以显示动作，但时间为 `—`。结果与实际速度、升力方向、位置、载荷、滚转率或油门偏离过大时丢弃，提示至少保持所设时间，失效状态会立即撤下提示。超过两秒未更新的计划不继续显示。

此功能是**人工键盘机动的候选参考**，模拟闭环通过不等于已经证明战雷内最快。它目前完成的是“从当前速度方向转过指定角度”。三九需要威胁视线，`VelocityGoal(kind="beam")` 仅保留接受完整三维视线的几何接口；尚未接入 RWR／截图识别、视线更新、保持三九或锁定解除判断，也没有从本机遥测猜测威胁方向。最省能量、稳定退出与通用六自由度最优控制不由本功能代替。

无窗口演示：

```text
python -m wt_overlay --demo --headless --duration 3 --aircraft su_27sm --mass-kg 23000 --turn-angle 90
```

## 指标含义

- **实际 SEP**：从真空速和高度时间序列得到的总比能变化率，单位 m/s。
- **比能高度**：`h + TAS² / (2g)`，单位 m。
- **爬升率／动能变化率**：同一个最长 1.2 秒窗口的变化率，两者相加等于实际 SEP。显示存在平滑时延。
- **过载**：8111 的机体法向 `Ny`，显示单位 g，与模型中的气动升力／重量分开。
- **迎角／侧滑角**：8111 的 AoA／AoS；俯仰和滚转使用地平仪读数。
- **加速度**：TAS 的平滑变化率，单位 m/s²，不代表完整三维加速度。
- **燃油／推力／总质量**：分别使用遥测燃油质量、明确 N 或 kgf 单位的各发动机推力之和、明确 `mass, kg` 字段。总质量不从燃油推算，也不使用手动模型参考质量代替。
- **静态参考 SEP**：所选 FM 在当前高度、给定参考质量、1g、干净构型下的预测。油门由模型设置选择全军推或全加力，不跟随实时油门。
- **参考峰值 SEP／TAS**：默认在当前 TAS 的 70%–130% 区间取 13 点。它不是全飞行包线的最优值，也不是到达目标高度的最短时间轨迹；边界和无效样本说明可在设置页查看。

模型参考不代表实际当前机动。实时机型未知或与所选 FM 不匹配时，预测停用；遥测能量仍可独立显示。演示模式始终标记为合成数据，不会自动接替失败的实时连接。

## 已实现与适用范围

8111 遥测处理和实际能量计算不限定为苏-27SM，但需要对应单位字段，尚未逐机型实测。未知可选字段保持缺失，不从燃油推算总质量，不把机体 Ny 当成任意姿态下的 L/W。

内置目录按 **空战历史（Air RB）BR ≥ 12.0，包含 12.0** 筛选，共 **138 架机型、113 份独立 FM、10 个国家**。范围取自 War Thunder Datamine 的 `wpcost.blkx`（`unitMoveType=air`、`economicRankHistorical>=33`）与 `shop.blkx` 中的机型键交集，排除不在科技树目录中的导弹测试及击杀奖励专用机。分房权重按 `round(1 + economicRankHistorical/3, 1)` 转为 BR。

数据固定在 **2026-09-20 / 2.59.0.16 / `371120bedae88b59fa0fa34c04566e83da64eed6`**，不随游戏升级自动变化。[完整机型目录](data/fm/catalog.json) 保存中英文名称、国家、BR、机型到 FM 的映射、原始路径和 SHA-256；同一 FM 的不同国家或型号保留独立身份。目录包含 F-15C 金鹰、苏-27SM、歼-11B 以及该版本满足范围的所有 14.7 机型。

文件加载会核对固定版本的内容哈希；任意新版或修改过的 FM 不会直接套用。气动核心移植自 Gaijin `polares`，推力算法参考 WTAPC。部件组装使用标准大气、共同来流、安装角、中立舵面、零侧滑和零转动率假设，**没有经过游戏验证**。

当前不计算下洗、流动惯性、力矩配平、挂载／损伤／改装额外阻力及发动机瞬态。仅支持干净构型、稳定全军推／最大增推；无增推档的 M-346FA 使用全军推。有增推档时沿用来源表的 WEP 倍率，未模拟水喷射等增推持续时间。发动机数量按 FM 的 `EngineN.Type` 逐台解析；Yak-141 前飞关闭升力发动机，Harrier 按前飞喷口状态处理。推力表只在节点完整的区间插值，缺节点和超界均返回不可用；歼-8F 的推力表未标记 `VelocityType`，暂按 TAS 解释，这是未经游戏验证的输入约定。作者对 WTAPC 喷气推力准确性的限制同样适用。

省略迎角时求 `L = n·m·g`，其中 `n` 定义为气动升力／重量；这不是纵向配平。静态接口中的航迹角不自动把 `n` 乘以余弦。若要指定近似匀速直线爬升的升力需求，可由调用方在适用条件下指定 `n ≈ cos(γ)`。

**特殊 FM 结构的近似：**

- F-14、狂风共 10 架变后掠翼机型：设置页显示“固定参考后掠”，范围 0–100%，默认 0%；也可用 `--sweep 50`。按 FM 的 `Sweep` 节点使用对应翼展、面积和 polar，节点间线性插值部件受力。整条 SEP／爬升参考使用选定的固定后掠比例，不复刻游戏自动后掠规律；应将游戏后掠设置保持一致，改变后掠需重新计算。0–100% 是控制比例，不是角度数值。
- 旧格式 F-4、MiG-21 Bison 共 10 架：机翼合并 `Aerodynamics` 与 `NoFlaps`，水平／垂直尾翼使用显式面积、宽度／高度和安装角。旧格式没有单独给出机身参考面积、跨度，暂取机翼面积和翼展作为机身 polar 的参考尺度；这部分组装是项目近似，不能据此声称复刻游戏 FM。
- 数据中的相同标量重复值会合并，不同值冲突仍拒绝；静态气动力不使用的第 6 条 Mach 曲线（焦点移动）不参与求值，其余有效曲线保持原有校验。

以上机型均已接入静态 SEP 和爬升接口，数值可计算与游戏内准确性是不同层面的验证。键盘转向参考及其限制见上文；通用最短时间／最省能量六自由度机动、RWR 识别和来袭导弹预测尚未实现。

## 无图形检查

任何装有 Python 3.11+ 的系统都可以运行无窗口演示：

```text
python -m wt_overlay --demo --headless --duration 2
python -m wt_overlay --demo --headless --duration 2 --model data/fm/su_27sm.blkx --mass-kg 23000
python -m wt_overlay --demo --headless --duration 3 --model data/fm/su_27sm.blkx --mass-kg 23000 --climb-altitude 8000 --arrival-speed-kmh 1200
```

输出为带单位字段的 JSON 行，`climb_guidance` 包含阶段、目标 TAS／IAS、当前航迹角、目标航迹角和角度误差。`--climb-altitude` 开启引导，`--arrival-speed-kmh` 可省略。实时连接失败时输出无效状态，不生成替代演示数据。模块与集成测试：

```text
python -m unittest discover -s tests -v
```

安装依赖后，测试还会覆盖 Qt 离屏绘制的透明通道、布局切换与保存、失效数据清空；未安装 PySide6 时这些图形测试会跳过。无图形运行无需安装 PySide6。Windows 原生窗口行为和 WT 客户端对照试飞仍需在目标环境验证。

算法版本、数据来源及复用许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
