# WT_overlay

War Thunder 空战研究工具集：Windows 8111 透明能量 HUD（能量指标、爬升引导、进攻辅助）、无画面空战模拟器与交互沙盘、强化学习空战副驾驶训练，以及战雷回放导入与导弹模型对照。所有工具只读取本机 8111，不注入游戏、不读内存、不发送任何键鼠输入；玩家负责全部操作与发射。

本 README 在所有分支上保持同一份，按功能写；某个功能是否在当前分支里见下文「分支」。

## 交互空战沙盘

在项目目录运行 `python -m wt_overlay.sandbox`，或在 Mac 双击 `start_sandbox.command`、Windows 双击 `start_sandbox.cmd`。浏览器自动打开本机 `http://127.0.0.1:8765/`，无需安装额外依赖；仍需 Python 3.11+ 与相邻 `../missle_sim`。可用 `--missile-sim /path/to/missle_sim`、`--port 8766` 或 `--no-browser`。

页面从准备阶段开始。选择 1v1 或 2v2 预设；每队最多 16 架，点击「部署」再点地图放置，拖动飞机可修改位置，右侧可编辑机型、挂载、数量与初始状态。「3D 战场」以真实米制 ENU 位置和高度显示飞机／导弹；拖动旋转、Shift + 拖动平移、滚轮缩放，也可切到「俯视布置」。「开始」「暂停」「推进 1 s」「重置布置」控制同一个世界的时钟；倍率是期望推进速度，实际倍率显示计算进度。

推演中点选飞机，可下达航向／高度／速度或地图目的地，也可「进入键盘驾驶」：点战场取得键盘焦点，W/S（或上下箭头）拉起／下压，A/D（或左右箭头）滚转，＋/－调油门，空格打开减速板。驾驶模式使用现有 `KeyboardCommand`（50% 操纵幅度）；人工导航使用 `FlightCommand`，均保留真实响应与惯性。暂停、失焦和退出驾驶释放按键；右侧可返回自主脚本。人工导航／驾驶下雷达自动 TWS 搜索，导弹和箔条由按钮控制，发射仍需要该飞机实际观测的雷达航迹并通过现有发射检查。旁观相机与飞行员有限视野相机独立，世界真值不会传给自主脚本。

页面也能加载回放：列表读取 `outputs/engagements/wt_real/`（由 [战雷回放工具](#战雷回放工具) 导入）和 `outputs/sandbox/run-*/replay.jsonl`。「原样回放」完全按记录的位置、速度和事件播放，不经过任何模型，姿态为估算（俯仰取速度方向，滚转按协调转弯）。暂停后可从当前时刻「接管」：选中的飞机改由我们的飞行模型和脚本／人工／键盘驾驶推进，其余飞机继续钉在回放轨迹上，回放里真实发射过、且我们有模型的导弹按原时刻重新发射。用于回答“那一刻换个打法会怎样”，设计见 [docs/sandbox_replay_spec.md](docs/sandbox_replay_spec.md)。

每次推演在 `outputs/sandbox/run-…/` 自动保存场景、既有 JSONL 回放和结果；结束后可在页面下载。运行中保存的是未完成结果，重置或关闭服务将未完成对局记录为中止，不产生虚构终局。「寿命上限」指仿真允许的导弹飞行时间，额外脱靶原因未单独记录时保持未知。当前仍是平地、现代导弹空战的研究沙盘，沿用下文模拟器的模型边界。

## 无画面空战模拟器

在项目目录运行 `python -m wt_overlay.sim`，默认完成一场固定种子的 F-15C 金鹰对苏-30SM2 1v1 导弹交战。需要 Python 3.11+ 和相邻目录 `../missle_sim` 的现有导弹模型；此入口只使用标准库，独立于 HUD、游戏遥测和 RL 训练。可指定模型目录：`--missile-sim /path/to/missle_sim`。

```text
python -m wt_overlay.sim --scenario data/sim/duel.json --out outputs/headless/duel
python -m wt_overlay.sim --scenario data/sim/duel.json --seed 2 --out outputs/headless/seed2
```

[示例场景](data/sim/duel.json) 的 `teams` 包含两个各有一架飞机的队伍；`position_m` 和 `velocity_mps` 分别是东、北、上方向的位置（m）与速度（m/s）。可改机型、导弹及数量、脚本类型 `archetype`（left/right/middle/crawler/rusher）、技能 `skill`（normal/top）、初始状态、`seed`、`time_limit_s` 和 `map_half_m`。可选 `chaff`、`mass_factor`、`rcs_ratio`、`flame_probability`；未指定的装备和脚本参数按现有对局模型与种子抽样，实际值会写入输出。`missile: null` 表示无挂载。场景拒绝未知字段、不支持的挂载和无效初始值。

输出目录包含 `scenario.json`（请求与实际参数）、`replay.jsonl`（0.25 s 世界帧、48 Hz 全精度导弹状态、事件）和 `result.json`（终局、发射／命中／未命中、仍在飞行的导弹、导弹错误、FM 越界次数和性能统计）。雷达／目视／告警的出现与消失记录的是飞行员实际收到的观测；回放中的世界真值仅供分析。脚本沿用有限视野相机与共同的意图执行器。`python scripts/plot_engagement.py --help` 可查看既有轨迹绘图入口。

相同场景和种子在相同模型与运行环境下可直接比较回放文件及其 `replay_sha256`；结果比较只排除 `performance`（墙钟时间与性能计数）字段。Python 调用可使用 `from wt_overlay.sim import build_simulation, result_document`，以场景字典构建世界，然后 `sim.step()`（1/48 s）或 `sim.run()`，最后 `result_document(sim)`。完整命令正常结束返回 0；记录到导弹错误或 FM 越界时仍保存结果并返回 1。时间上限／僵局允许平局，未结束的导弹明确标为未决；未命中的额外原因没有记录时保持未知。

此版本沿用现有平地、飞机操纵与传感器近似，以及“引信触发即击落”的规则；完整运行和可重复性不代表已校准到战雷实际对局。

## 强化学习训练

目标是训练一个只看玩家可得信息的循环 PPO 策略，在整场空战里给出接敌、发射、支援、防御和再进攻的建议，再翻译成 HUD 提示；策略不操控飞机。设计、环境与训练规格见 [docs/rl_design.md](docs/rl_design.md)、[docs/rl_env_spec.md](docs/rl_env_spec.md)、[docs/rl_training_spec.md](docs/rl_training_spec.md)。

- 环境：`wt_overlay/rl_env.py` 的 `MatchEnv`，建立在对局模拟器（`flight`、`engagement`、`sensors`、`match`、`archetypes`）之上；对局与人群配置在 `data/match/`。`python -m rl.check_env --env wt_overlay.rl_env:MatchEnv --config '{...}'` 检查环境契约。
- 训练：`python -m rl.train run --config smoke|workstation|gpu_cluster|file.json --run-dir D [--set a.b=v ...]` 依次执行脚本数据采集、行为克隆和 PPO，已完成的阶段自动跳过；被时限或 `SIGUSR1` 停下时先存档并返回 75，重跑同一命令继续。`--set` 的值按 Python 字面量解析（写 `True`／`None`，不是 JSON 的 `true`／`null`）。
- 集群：`rl/launch/workstation.sh`（48 核上限，拒绝在 sharedhost 上运行）和 `rl/launch/gpu_cluster.sbatch`。
- 评估：`python -m rl.eval_replay` 让最新检查点打固定对局并录下回放（含留出机型）；`python scripts/rl_dashboard.py` 在本机网页查看训练曲线和回放，可用 `--remote host:path` 同步远端运行。
- 冻结策略：[models/](models/README.md) 保存 1v1 `s1_1v1_r304.pt` 与 4v4 `s2c_4v4_r554.pt` 的纯权重导出，用 `rl.eval_replay.load_actor` 加载。

测试：`python -m unittest discover -s rl/tests`。

## 战雷回放工具

把真实战雷对局与我们的模型放在一起比较，主要用来校准导弹模型（波门、下视、多径）。

1. `scripts/wt_replay_import.py`：读取 missile_sim 回放解析器导出的 `match_export.json`（`.wrpl` 需先用该解析器导出，命令见脚本说明），转成与模拟器相同的回放 JSONL，写到 `outputs/engagements/wt_real/`。每个字段注明来自回放还是推断。
2. `scripts/wt_replay_missiles.py`：逐枚导弹的发射几何、离轴角、最近距离、末段是否在波门内、箔条等，并把真实与模拟的命中率并列汇总。

导入的回放也可以在 [交互空战沙盘](#交互空战沙盘) 里原样播放或接管。

## 8111 能量 HUD

Windows 8111 透明能量 HUD 与静态 SEP 研究原型。显示层使用 PySide6；遥测、能量与 FM 计算只使用 Python 标准库。

### 在 Windows 上运行

使用 Python 3.11 或更新版本。将整个目录复制到 Windows 后，双击 `start_windows.cmd`。启动器会在项目的 `.venv` 中创建独立环境，并在首次运行时安装 PySide6，因此首次运行需要联网。准备完成后，图形界面使用 `pythonw.exe` 独立运行，双击启动产生的命令窗口随即关闭；`--headless` 和 `--help` 保留控制台输出。图形启动出错时会弹出错误提示，记录保存在 `%LOCALAPPDATA%\WT Energy\startup.log`。

将战雷显示模式设为 **全屏窗口**。默认连接本机 `http://127.0.0.1:8111`；HUD 自动跟随战雷窗口，切出游戏或最小化后隐藏。每次启动都会打开设置，关闭设置即可回到游戏；随后可用 `Ctrl+Alt+S` 或托盘菜单重新打开。没有有效遥测时指标显示 `—`。未检测到游戏时，可进入布局模式或合成演示预览。

先查看合成演示，可在项目目录的终端运行：

```bat
start_windows.cmd --demo
```

默认按 8111 返回的机型自动加载内置 FM，无需逐个找文件。设置页的“机型”列表可按中英文名称搜索，也可手动指定。机型不明或不在目录中时停止模型预测。

手动选择苏-27SM，使用 **23,000 kg 参考总质量**：

```bat
start_windows.cmd --aircraft su_27sm --mass-kg 23000
```

也可通过托盘菜单或 `Ctrl+Alt+S` 打开独立设置，切换实时／演示模式、选择机型或 FM 文件、输入质量和挂载、切换是否允许最大推力。23,000 kg 只是示例输入，不是自动识别的本机重量。手动质量不会随燃油或机型自动变化，换机后需要重新输入适用的总质量；清空质量框后点“应用”恢复自动。

总质量按以下顺序取用：手动输入 > 遥测中明确的 `mass, kg` 字段 > **估算**。8111 实际只提供燃油（`Mfuel, kg`），不提供总质量，所以通常走估算：`FM EmptyMass + 实时燃油 + 挂载`，随燃油消耗自动更新。武器、吊舱和弹药质量 8111 不提供，需要在设置页“挂载 / kg”或命令行 `--payload-kg` 手动填写，默认 0。估算只在所选 FM 与游戏机型一致时使用，HUD 的总质量后标“估”。滑油、机组等 FM 中未计入空重的小项未加入。

机型切换会取消旧爬升规划并重新计算。手动选定的机型仍须与实时机型匹配；“自动识别机型”可恢复自动切换。设置页“当前模型”显示自动识别结果及游戏返回的机型标识；“手动载入 FM 文件…”是可选按钮，不代表自动识别失败。短暂读取失败时保留已加载模型但停止预测，收到同一机型的有效数据后恢复；加载失败每两秒重试。合成演示不自动选择机型，需要手动选择或使用 `--aircraft`。原有 `--model data\fm\su_27sm.blkx` 继续加载最初版本的回归样本。

显示与分组交互参考 [WTRTI 的 OSD / Groups](https://mesofthorny.github.io/WTRTI/features/)，使用 Qt 自行实现，并未复用 WTRTI 的程序或素材。战斗 HUD 背景完全透明，只绘制带描边的文字；无标题栏，不接受焦点，鼠标穿透到游戏。

布局模式中，拖动“飞行状态”“实际能量”“动力与燃油”“静态参考”四个指标组；退出后恢复鼠标穿透。位置以游戏窗口内的相对位置保存，字体、字号、强调色、各组和各指标开关也会保存到本机用户配置。默认字号为 11，旧版配置首次升级时也会缩小，之后保留用户选择。设置中可以恢复默认位置、选择备用屏幕或关闭自动隐藏。关闭设置会完成布局并收起；退出程序使用设置或托盘中的“退出”。若系统托盘和设置热键都不可用，关闭设置会退出程序，避免留下无法操作的 HUD。

战斗 HUD 只显示指标名、数值和单位，组标题仅在布局模式显示。连接状态、字段定义和模型说明放在设置页；演示模式保留简短的 `DEMO` 标记。当前真空速不在 HUD 中重复显示。

设置页提供 22 项独立开关，默认启用 17 项：过载、迎角、侧滑角、俯仰角、滚转角、SEP、比能高度、爬升率、动能变化率、加速度、燃油、推力、油门、总质量、参考 SEP、参考峰值 TAS、参考峰值 SEP。航向、垂直速度原始值、表速、高度、马赫数可按需开启；第一台发动机油门和模型所用总质量默认显示。字段缺失时显示 `—`，不会用演示值补齐。

热键若被其他软件占用，设置界面会显示注册失败，仍可使用托盘菜单。独占全屏覆盖不在当前保证范围内；Windows 原生穿透、全局热键和游戏窗口跟随需要在 Windows 游戏环境实测。

### 指标含义

- **实际 SEP**：从真空速和高度时间序列得到的总比能变化率，单位 m/s。
- **比能高度**：`h + TAS² / (2g)`，单位 m。
- **爬升率／动能变化率**：同一个最长 1.2 秒窗口的变化率，两者相加等于实际 SEP。显示存在平滑时延。
- **过载**：8111 的机体法向 `Ny`，显示单位 g，与模型中的气动升力／重量分开。
- **迎角／侧滑角**：8111 的 AoA／AoS；俯仰和滚转使用地平仪读数。
- **加速度**：TAS 的平滑变化率，单位 m/s²，不代表完整三维加速度。
- **燃油／推力／总质量**：分别使用遥测燃油质量、明确 N、kgf 或 `kgs`（8111 对 kgf 的标注）单位的各发动机推力之和、模型实际使用的总质量（来源见上文，估算值标“估”）。
- **静态参考 SEP**：所选 FM 在当前高度、参考质量、1g、干净构型下的预测，**跟随实时油门**（`throttle 1, %`，多发按第一台油门套用到全部发动机）。0–100% 按 FM 发动机 `Mode` 表的 `Throttle→ThrustMult` 分段线性插值（如苏-27SM：0% 为军推的 5%，90% 为 85.2%）；100% 以上在全军推与全加力之间线性过渡，到最强增推档的油门值（通常 110%）为全加力。读不到油门时按设置的全军推／全加力计算。该值是稳态推力，8111 油门是指令油门，不含发动机转速滞后；实际 SEP 以“实际能量”组为准。
- **参考峰值 SEP／TAS**：默认在当前 TAS 的 70%–130% 区间取 13 点。它不是全飞行包线的最优值，也不是到达目标高度的最短时间轨迹；边界和无效样本说明可在设置页查看。

模型参考不代表实际当前机动。实时机型未知或与所选 FM 不匹配时，预测停用；遥测能量仍可独立显示。演示模式始终标记为合成数据，不会自动接替失败的实时连接。

### 爬升引导

爬升引导默认关闭。加载匹配的 FM 并设置总质量后，在设置页输入目标高度和可选的到达最低 TAS，点击“应用目标”。高度单位为 m，速度单位为 km/h；速度留空时，选择目标高度上静态 SEP 最大点的速度作为到达门槛。目标设置会保存，开启状态不随重启恢复。

使用 `Ctrl+Alt+C`、托盘菜单或设置中的开关启用。规划按实时油门计算（无油门读数时按模型设置的全军推／全加力），以俯仰操纵跟随指示条：白点在右侧时抬高，在左侧时压低，使白点保持在中央绿区。绿区对应航迹角误差 ±1.5°，整条刻度为 ±12°，超出后白点停在端点。它比较的是 **目标航迹角与实际航迹角**；实际角度由垂直速度和 TAS 计算，经 0.5 秒低通后同时用于“当前航迹角”数值和白点。不会把机头俯仰角当成航迹角。

引导组显示“加速／爬升／收平／到达”、目标 IAS、当前航迹角、目标航迹角和剩余高度。需要先平飞加速时，目标速度取参考线上后续进入爬升的速度；爬升后取随能量更新的跟踪速度。两者都换算为当前高度下的表速供跟飞。接近目标高度时逐渐收平，达到高度误差 ±25 m、TAS 不低于到达门槛、航迹角绝对值不超过 1.5° 后显示“到达”并收起白点。软件不发送任何飞行控制输入。

能量、推力和速度跟踪计算始终使用 TAS。HUD 的目标 IAS 按同一时刻的遥测换算：`IAS_target = TAS_target × IAS_current / TAS_current`；IAS 缺失、为零或无效时显示 `—`，角度引导仍可工作。这是当前状态附近的局部比例估计，没有另建皮托管可压缩性或仪表修正模型，不能保证大幅速度变化时的精确换算。到达速度设置及原有命令行参数仍明确使用 TAS，已有目标的单位不会改变。合成演示的 IAS 由标准大气密度生成，仅用于演示显示。

爬升组可在启用后进入布局模式独立拖动，沿用透明背景和鼠标穿透。关闭引导会立即隐藏该组，并取消后台规划；其他指标保持显示。总 HUD 开关仍控制所有组。数据失效、机型不符、质量缺失或模型不支持对应状态时，不显示角度指令。滚转角绝对值超过 30° 时提示“改平”。

规划使用比能高度 `E_s = h + V²/(2g)`，在每条等能量曲线上搜索 `P_s` 最大点，再连接成速度参考线；它与原有“同高度局部 SEP 峰值”指标各自独立。搜索限制为 0 至目标高度、80–650 m/s，并由 FM 的有效包线进一步约束。每个能量层间隔不超过 250 m，采用全区间 49 点粗搜和两次局部细化，无有效正 SEP 路径时停止规划。计算在后台进行；目标、机型、FM、模型推力档或手动质量改变后重新计算。自动质量累计变化超过 1%、油门变化超过 5 个百分点或跨过 100%（进出加力）时在后台更新，新规划完成前继续沿用旧规划。

实时跟踪采用 `a_cmd = V_ref'(E_s)·P_s + 0.08·(V_ref−V)`，再由 `h_dot_cmd = P_s−V·a_cmd/g` 得到航迹角。反馈优先使用遥测 SEP，并施加 1 秒低通；能量窗口尚未就绪时使用静态模型 SEP。角度限于 −5° 至 45°，目标指令以 2 秒时间常数平滑，变化率上限为 1°/s。数据中断或重新开启时，以新的当前角度初始化。接近末端时，将参考线平滑过渡到目标高度对应的等能量速度，并用剩余高度／12 秒限制爬升率，避免把整条参考线的末端当作瞬间可完成的拉起或收平。

这里实现的是**经典能量近似下的 SEP 最大参考线，以及带终端收平的人工跟踪引导**，不是完整瞬态动力学下经证明的最短时间解。等能量线方法假定高度与速度之间可快速交换；实际跟踪器限制下降、角度和变化率，转场、操纵滞后和收平会改变用时。到达速度是下限，不保证恰好以该速度到达，也不同时保证到达速度最大。离散搜索可能漏掉窄峰，参考线跳支和捕获段没有最优性保证。

规划沿用现有静态推力、部件气动和 1g 干净构型计算，以规划时刻的油门和质量为常数，不预测爬升途中的燃油消耗，不计挂载阻力、配平或发动机瞬态；大航迹角时的升力需求变化也未重算。内置机型通过同一接口生成参考线；仅在所选质量、构型和目标存在有效正 SEP 路径时提供引导。闭环检查使用理想质点运动和两秒操纵滞后，**不是战雷内的最优爬升验证**。完整模型范围见下文。

### 进攻辅助

在设置页“进攻辅助”中选择导弹、假设敌机及其速度、对手水平（普通：85% 会躲，其中 60% 做对；高手：总能躲且动作正确）和发射方式。三个显示都是“现在发射”的命中概率或发射区边界，由离线蒸馏的命中概率网络（`wt_overlay/pk.py`，训练范围 2–45 km）给出；HUD 只查表和求值，不推断敌机状态，目标运动由玩家从 B 显光点读出。

- **进攻动向图**（`Ctrl+Alt+K`）：圈为发射距离，方向为目标光点在 B 显上的移动方向（往下 = 迎头），颜色为命中概率：≥50% 红、25–50% 黄、<25% 灰、打不到为暗色。
- **B 显发射区**（`Ctrl+Alt+B`）：在布局模式中把框拖到游戏 B 显上并调成同样大小，量程和方位范围需与游戏一致。画出迎头／背离 Rmax 和迎头命中概率 50%、25% 的边界，目标假设为同高度直线飞行。贴地目标另见下文「B 显贴地模式」。
- **高度侧视图**（`Ctrl+Alt+V`）：横轴为发射距离，纵轴为目标高度减本机高度，线型与 B 显发射区一致。

主动弹没有发射告警；对手在导弹开机（约 16 km）、看到动力段尾焰或被 STT 锁定时才察觉。敌机速度、同高度、9 g 规避和箔条效果都是假设，没有经过游戏验证。离线表由 `scripts/escape_window.py`、`scripts/build_*_table.py` 和 `scripts/distill_pk.py` 生成，数据在 `data/` 下。

#### B 显贴地模式

<summary>原说明（未再维护）</summary>

在设置页的“键盘转向引导”选择 **30°／45°／90°／120°**，设置允许损失高度、最低 TAS 和响应参数，然后用 `Ctrl+Alt+T` 开启。首次取得连续姿态数据时记录初始速度方向，以后显示相对此方向的三维夹角；不累计盘旋路径角度，也不把机头航向变化当作速度方向变化。

HUD 显示当前动作、动作段编号、预计换步时间、下一步、油门、减速板（若该计划用到）、目标转角、已转角度、剩余角度和参考用时。动作使用“左滚／停止滚转／右滚”与“推杆／松杆／拉杆”的组合；油门单独显示“收油／保持／加油”及当前值、本段结束时的固定目标值。减速板为展开或收起。默认每段至少保持 1.2 秒，相邻相同动作合并，最多四段；最后一段可以因达到目标提前结束。跟完当前段、按预告切换下一段；执行期间不反复换成新搜索的首动作。按游戏中自己的键位执行；软件不会读取或发送按键。方向舵保持中立。开启转向引导会关闭爬升引导，反之亦然。

**歼-16 等缺少地平仪字段的飞机：** 在正飞、机翼水平、停止滚转且小侧滑时按 `Ctrl+Alt+A`，或使用设置页的“平翼校准”。校准会重新捕获本次转向起点。此后结合 `Wx, deg/s`、航向、TAS、Vy、AoA 和 AoS 连续估计姿态；HUD 单独显示“姿态估计”，原始俯仰／滚转遥测字段仍保持缺失，SEP 与爬升功能继续使用原始数据。只要原始地平仪姿态有效，就优先使用原始值。首次使用须小幅右滚核对估计滚转是否正向增大；若方向相反，在设置里改选“反向 Wx”，恢复平翼后重新校准。方向选择会保存，校准姿态不会跨重启保存。

姿态估计采用机体滚转率关系 `dφ = p·dt + sin(θ)·dψ`，结合速度竖直分量与 AoA/AoS、滚转角的几何关系解俯仰，包含航向跨越 360° 的处理；没有直接把 Wx 当作欧拉滚转率，也没有把 Ny 当作升力反求姿态。平翼是用户提供的初始条件，软件无法从缺失的仪表验证它。`Wx` 的机体系解释和正负方向、零风假设、遥测同步误差及累计漂移仍需游戏内核对，单个样本与合成轨迹测试不构成实机校准。读数中断、采样间隔超过 0.6 秒、换机、接近垂直（解出的俯仰达到 ±75°）或姿态分支不确定时要求重新校准；每次校准最多使用 60 秒。无法用此方法保证所有姿态下的精确三维机动。

首次达到目标角度后显示“到达／松开机动键”，状态保持到重新开始；松键是结束本次按键机动的提醒，不保证飞机立即停止转动，也不规划后续如何保持新方向。`Ctrl+Alt+R` 或设置页、托盘的“重新开始转向”重新捕获起始方向。关闭开关立即隐藏转向组。转向设置和位置会保存，开启状态不会随重启恢复。

短暂断线、姿态采样不连续或低于所设速度／高度下限会撤下动作，保留初始方向和高度下限；恢复连续有效数据、回到限制范围后继续。姿态读数缺失时保留最后一次有效进度并标为“最近转角／最近余角”，不会冒充实时更新。原始姿态的数据中断超过 2.5 秒、换机或修改质量／FM／推力档／后掠后，已捕获目标的会话须重新开始；估计姿态还受上述更严格的校准连续性限制。缺少必要读数时不提供动作。高度限制是相对开始高度的损失上限，使用海拔高度，并不包含地形避障。

几何读数仍完整、但迎角超出 ±60° 查询范围、侧滑过大等原因使气动力预测不可用时，切换到“机动跟随”，保留实时转角与执行提醒。它用最近 0.6 秒、至少三个样本的转角趋势：有进展时显示“保持机动”，没有增加时显示“检查转向”，余角小于转角变化率乘以所设反应时间与俯仰响应时间之和（最低 2°）时提示“准备松键”，到达后显示“松开机动键”。提醒不再给出最优按键组合、油门目标、动作段或预测用时；油门仅显示当前读数。该跟随模式不把机体 Ny 当作 L/W，是按已发生的机动提供进度提醒，不证明当前动作最优或可按预计角度停住。气动预测恢复时保留跟随提示，直到接受新的分段计划。具体模型原因保留在设置页。

**动态参考的定义与边界：**

- 平动是三维质点模型：速度向量与垂直于它的升力方向为状态，包含重力、升力、阻力及推力的切向／法向分量；不强制水平转弯。升力方向随滚转和航迹转动更新。气动力使用所选 FM 的同一套部件 polar，推力使用原有发动机表；既有 SEP 和爬升公式保持原样。
- 迎角是连续预测状态，由实时 AoA 初始化。气动力直接按每个部件的有效迎角调用完整静态 polar，包含临界迎角之后的升力与阻力；某个部件越过临界点不再使整机预测停用。转向查询范围为 **−60° 至 +60°**，这是前向飞行的项目计算边界，不是飞机失速角。载荷 `L/(mg)` 由每一步的迎角、速度、高度和 FM 重算，不使用机体 Ny 代替，也不把当前载荷夹到设定值。已有静态 SEP／爬升求解范围保持原样。
- 所设正／负载荷仍作为按键目标。迎角目标沿完整曲线逐段找交点，不在整条非单调曲线上二分；按住俯仰键时选最接近当前迎角的解，松杆时选接近零迎角的解。不可达的载荷目标限制到采样曲线的最近极值。迎角以所设俯仰响应时间一阶趋近目标，气动力在过渡途中逐步计算；反应延迟期间保留当前迎角。转向积分从机型加载时预计算的 Mach–迎角 \(L/q\)、\(D/q\) 表查升阻力（0.1° 迎角网格，马赫节点含 polar 断点及跨音速加密）；表在节点上与直接 polar 装配一致，节点之间双线性插值，仍是有限采样近似。静态 SEP／爬升仍直接调用 polar，不走该表。没有增加动态失速滞后、舵面力矩或飞控／教官模型。
- 当前 FM 推算载荷若已超出设置范围，仍可搜索恢复动作；预测载荷不允许超过起始超限程度，沿用 0.2 的数值容差。按键目标继续使用所设正／负载荷范围，恢复途中可能仍暂时超限。速度与高度约束不放宽；如果没有满足这些条件的候选，就不提供分段计划。
- 速度方向由罗盘、俯仰、滚转、AoA、AoS 重建水平投影，再用 `Vy/TAS` 确定航迹角。采用东、北、上坐标，正俯仰为抬头，正滚转为右翼下沉；沿用现有姿态字段的符号约定，仍需在 Windows 中逐机型核对。风为零，不能据此恢复有风情况下的精确地速矢量。滚转率从连续升力方向的转动估计，排除航迹转动分量，并用 0.25 秒低通；没有把欧拉角变化率直接当作机体系角速度。
- 滚转、俯仰、油门各取 `−1/0/+1`，共 27 种组合，油门边界处跳过无效的增减动作。拉杆／推杆对应所设正／负载荷目标，中立俯仰近似抵消升力方向上的重力分量；滚转中立按响应时间衰减滚转率。减速板是展开／收起开关，不进入这 27 种按键的穷举；前两段可额外比较“现在展开”或“稍后展开”，并保留若干展开首段。内部开度按 FM 的 `AirBrakeSpeed` 在 0–1 间变化（苏-27SM 为 0.5，约两秒全开）。附加阻力为 \(q\cdot S_\text{fuse}\cdot\texttt{AirbrakeCd}\cdot\delta\)，加在 polar 表外，不改变升力，也不写入机身 `CdMin`（以免过失速阻力上限或 Mach \(C_{D0}\) 曲线去乘这项）。`AirbrakesShift` 属力矩，`AirbrakeToThrust` 在当前目录均为 0，均未使用。8111 不提供开度，观测状态按收起处理；提示按当前计划给出。**这不是鼠标瞄准教官的恢复规律**：实际松键响应还受鼠标指向、教官、飞控、改装、机组和速度影响。
- 油门从实时读数开始，以默认 **50 个百分点/s** 增减；保持输入维持当前油门。允许加力且发动机有加力时搜索至 110%，否则至 100%，最低 0%。推力参考与静态 SEP 共用同一油门推力律（见“静态参考 SEP”），并加入默认 **1 s** 的一阶响应。初始推力状态按首个油门读数估计，之后按读数更新。**部分油门曲线和响应时间是项目近似，未经游戏标定**，不代表真实慢车、熄火或发动机控制律。油门变化速度、响应时间可在设置页调整。较低速度可能增大转向角速度，但升力能力也随速度变化，搜索仍检查最低速度和载荷约束，不固定要求收油。
- 默认满滚转参考速度 **120°/s**、滚转一阶时间常数 **0.35 s**、俯仰／迎角一阶时间常数 **0.6 s**（沿用旧配置的 `load_response_s` 数值）、人的反应时间 **0.3 s**、每段最短时间 **1.2 s**（可设 0.8–3 s；旧版低于 0.8 s 的保存值迁移至 1.2 s）。默认正／负载荷范围 **+9/−3**，最低 TAS **360 km/h**，允许损失高度 **500 m**，预测上限 **15 s**。这些是可调整的项目参考参数，**不是从每架飞机 FM 复刻出来或已用游戏数据标定的结果**；同一组参数会沿用到其他机型，需要重新检查。尚未实现按键试飞记录与自动辨识。
- 后台使用有限宽度的动作段搜索，最多保留 27 条不同首动作分支及各自完整动作序列，每段保持所设时间，积分步长不超过 0.15 s。减速板不进入这 27 种按键；搜完后对已有序列比较「现在展开」「稍后展开」「前两段都展开」。执行中若当前段被锁住，只改后面段的减速板。首次规划先预测人的反应延迟；执行中的接续规划从当前观测出发，不再重复反应延迟，并把尚未结束的当前段锁为第一段。在找到的候选中优先比较首次到达时间，同一步达到时再比较剩余比能。每次计算预算 0.8 s；有可用指令时后台仍可按该间隔接续规划。搜索剪枝、四段限制、离散步长、时间预算与近似模型均不支持全局最优保证。
- 搜索结果从最新观测重算后再决定是否接纳，不假定玩家已按上次预测飞过。只有重算后确实到达目标，才显示“参考用时”；只有部分转向进展时可以显示动作，但时间为 `—`。当前指令只要从最新观测接着做仍满足约束且不反向，就继续显示。显示换步只在观测仍跟上该时刻的预测时前进；没跟上就停在当前这一动，不按墙上的钟切到下一段。正在显示的那一段剩余超过 0.25 s 时不换首动作，除非旧方案已经不可行。新方案首动作不同时，在**同一段剩余时间**上比较：新方案到达而旧方案未到达，或剩余转角至少少 2°，才替换。同按键若被搜索延长，保留延长，不裁回锁定剩余。序列时间用完后仍显示最后一动并立即继续规划。实际超限或必要读数失效时撤下动作，保留有效进度。

此功能是**人工键盘机动的候选参考**，模拟闭环通过不等于已经证明战雷内最快。它目前完成的是“从当前速度方向转过指定角度”。三九需要威胁视线，`VelocityGoal(kind="beam")` 仅保留接受完整三维视线的几何接口；尚未接入 RWR／截图识别、视线更新、保持三九或锁定解除判断，也没有从本机遥测猜测威胁方向。最省能量、稳定退出与通用六自由度最优控制不由本功能代替。
